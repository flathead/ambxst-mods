# i18n System for Ambxst

## Overview

Full internationalization system for the Ambxst QuickShell desktop shell. Translates all user-visible strings with automatic language detection and manual override. Ships with English, Russian, and Spanish translations. Designed for easy contribution of new languages.

## Architecture

### Translation Files

Located in `translations/` at the project root.

**`languages.json`** -- registry of available languages with native display names:
```json
{
    "en": "English",
    "ru": "Русский",
    "es": "Español"
}
```

**`en.json`**, **`ru.json`**, **`es.json`** -- flat key-value JSON files. Keys use dot notation for context grouping. Values are translated strings with `%1`, `%2` for parameters.

Example (`en.json`):
```json
{
    "settings.network": "Network",
    "settings.bluetooth": "Bluetooth",
    "settings.theme": "Theme",
    "settings.system": "System",

    "bar.tooltip.controls": "Audio & Brightness Controls",
    "bar.tooltip.launcher": "Open Launcher",

    "bluetooth.disabled": "Bluetooth is disabled",
    "bluetooth.no_devices": "No devices found",
    "bluetooth.scan": "Scan for devices",

    "battery.charging": "Charging",
    "battery.remaining": "%1 remaining",

    "common.search": "Search...",
    "common.open": "Open",
    "common.delete": "Delete",
    "common.copy": "Copy",
    "common.copied": "Copied!"
}
```

Key naming convention:
- `module.element` for simple strings: `"settings.network"`, `"bluetooth.scan"`
- `module.context.element` for disambiguation: `"bar.tooltip.controls"`, `"battery.full_in"`
- `common.*` for reusable strings: `"common.open"`, `"common.delete"`

### I18n Singleton

Located at `modules/services/I18n.qml`. Registered as a singleton via the existing module system.

Core API:
- `t(key, ...args)` -- returns translated string, substituting `%1`, `%2`, etc. with args
- `language` -- current language code, bound to `Config.system.language`
- `ready` -- true when translations are loaded
- `availableLanguages` -- parsed from `languages.json`

Fallback chain: current language string -> en.json string -> raw key.

Loading mechanism:
- `en.json` loaded via FileView with `preload: true` (always available as fallback)
- Active language loaded via second FileView, path changes reactively with `language` property
- `languages.json` loaded via third FileView with `preload: true`

### Language Detection

When `Config.system.language` is `"auto"`, the system detects language from the OS. Sources checked in order:

1. `Qt.locale().name` (reads `LC_ALL`/`LC_MESSAGES`/`LANG`)
2. `Quickshell.env("LC_MESSAGES")`
3. `Quickshell.env("LC_ALL")`
4. `Quickshell.env("LANG")`
5. Fallback: `"en"`

First non-empty result is trimmed to 2 lowercase characters. Values `"c"` and `"po"` (POSIX) are skipped. The resulting code is checked against `languages.json` keys; if absent, falls back to `"en"`.

### Configuration

`config/defaults/system.js` -- add `"language": "auto"` to the existing data object.

Persisted to `~/.config/ambxst/config/system.json` via the existing FileView + JsonAdapter pipeline. Validated against defaults like all other config modules.

### Settings UI

Language selector added to **SystemPanel.qml** as a new section. Placed logically among other system-level settings (after Prefixes or at the top).

Widget: chip-selector or segmented switch showing available languages by their native names. First option is "Auto" (with detected language shown in parentheses). Selecting a language sets `Config.system.language` to the language code; selecting Auto sets it to `"auto"`.

## Migration Strategy

All hardcoded user-visible strings are replaced with `I18n.t("key")` calls. Approximately 300+ strings across 150+ files.

Migration order by module:
1. Settings panels (~150 strings) -- ShellPanel, SystemPanel, ThemePanel, BluetoothPanel, WifiPanel, BindsPanel, CompositorPanel, AudioMixerPanel, EasyEffectsPanel, AiPanel
2. Bar components (~30) -- tooltips, BatteryIndicator, Clock, ControlsButton
3. Player and dashboard widgets (~30) -- FullPlayer, CompactPlayer, QuickControls
4. Bluetooth/WiFi panels (~40) -- status messages, buttons
5. AI/Sidebar (~20) -- placeholders, buttons
6. Other modules (~30) -- notifications, lockscreen, launcher, overview, desktop

**SettingsIndex.qml**: only `label` and `subLabel` fields are translated. Search `keywords` remain in English -- they are technical terms and translating them provides no significant benefit.

### Import Convention

Every QML file that uses translations adds:
```qml
import qs.modules.services
```
(if not already imported) and calls `I18n.t("key")` inline.

## Contributor Workflow

To add a new language:
1. Copy `translations/en.json` to `translations/xx.json` (where `xx` is the ISO 639-1 code)
2. Translate all values. Do not modify keys.
3. Add an entry to `translations/languages.json`: `"xx": "Native Name"`
4. Submit a pull request

No code changes required beyond the two files.

## Scope Boundaries

**In scope:**
- I18n singleton with `t()` function
- Translation files for en, ru, es
- Auto-detection of system language
- Language setting in SystemPanel
- Migration of all hardcoded strings

**Out of scope:**
- RTL layout support (no RTL languages in initial set)
- Pluralization rules (use simple `%1` substitution)
- Date/time format localization (handled by system locale already)
- Translation of search keywords in SettingsIndex
